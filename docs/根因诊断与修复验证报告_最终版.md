# UR5e 残差 SAC-GAIL 插装：根因诊断与修复验证报告

日期：2026-09-18　｜　环境：MuJoCo UR5e peg-in-hole 仿真　｜　算法：冻结 BC 基座 + 可学习残差（SAC），奖励仅 GAIL/稀疏成功

---

## 0. 结论摘要（TL;DR）

1. **成功率"震荡不涨"的最根本根因不在算法，而在环境层**：控制器内层运动学求解器 TRAC-IK 使用 `Speed` 模式 + **5ms 墙钟超时**——返回什么解取决于当时 CPU 负载。同一随机种子、同一策略连跑两遍，成功率为 **20% vs 45%**；第 0 步动作逐比特相同，下一步观测已差 6.4e-4。在此之上的一切训练信号与评估数字都是噪声。
2. **修复**：IK 后端默认切换为**确定性 Pinocchio 局部 IK**（`UR5E_IK_BACKEND=pin`，设 `trac` 可恢复旧行为）。修复后同 seed 两遍 20 回合 rollout **逐帧完全一致**（观测哈希全等）；BC rollout 全程 13203 次 IK 调用未收敛率仅 **0.02%**（最大残差 1.43mm / 1.87°），求解质量无问题。
3. **"残差是不是太小"——已定量验证：不是首要根因**。专家状态分布上学到的残差 RMS=0.0035、p99=0.0121、对 ε=0.05 的饱和率 0%；而 ε=0.10 消融反而更差（固定种子 50 回合仅 20%，失败态占 23/50）。
4. **修复后的确定性基线**：BC 50 回合固定种子成功率 **14%（7/50）**，且失败全部是"超时未插到底"（旧 TRAC-IK 环境下的 32%–40% 基线不可复现，属于噪声测量）。
5. **确定性环境下的完整消融链（v10–v15，全部 n=20 固定种子评估）**：纯稀疏 / +演示预充 / +UTD×15 / +超时 bootstrap 修复 / +熵标定修复 / +γ=0.99——**六个配置全部平贴 BC 基线（10–20% 带内），无一产生稳定上升**。过程中发现并修复了四个真实缺陷（详见 §5）。
6. **最终定量结论**：critic 已收敛（Huber loss 0.0015）但其动作面在残差球内的方向对比度（~0.008）比 TD 拟合噪声（~0.17）低 20 倍，方向探针命中率 5/8≈抛硬币——**actor 无坡度可爬。这是"小幅度残差 + 长视野 + 纯稀疏奖励 + 接触任务"的结构性错配**（§6），出路在任务分层/残差作用对象上移/critic 方差压制，不在调参。
7. **控制器已升级为操作空间控制（OSC，免 IK 内环）**：SERL 范式 JᵀΛẍ+零空间+重力补偿，1kHz 直接力矩控制。确定性为构造性保证（两遍逐帧一致）、速度 ~2 倍、接触安全（0 力超限）。叠加**腕部 F/T 惯性补偿**（Newton-Euler 工具逆动力学，§9.5）后 BC 基线 **12% vs IK 路径 14%**，已基本追平（残余差距为 BC 演示采集动力学失配，属残差 RL 要在线修正的对象）。**当前环境默认 `UR5E_CTRL_MODE=osc`**，设 `ik` 可切回 IK+CTC 路径复现 §3–§6 的全部数字。

## 2. 残差尺度验证（用户问题一：是否残差太小）

定量证据（v8 ε=0.05 checkpoint，专家状态分布）：

- 学到的残差：RMS=0.0035，max|ã|=0.0135，p99=0.0121，**对 ε=0.05 硬上限的饱和率 0.0%**——网络远未用满修正幅度，ε 不构成硬约束；
- 训练日志 residual_rms≈0.028（cap 0.05）；
- BC 输出相对专家动作的误差：RMS=0.0688，任一维误差 >0.05 的样本占 12.2%（姿态第 4/5 维各 22.4%/20.6%）——**确实有需要更大修正的样本**；
- 但 ε=0.10 消融（其余全同）：固定种子 50 回合仅 **20%**，失败态 state4 占 23/50——更大的残差幅度带来更多越界/力超限，净效果更差。

**结论：ε=0.05 不是瓶颈；放大残差在当前环境条件下反而有害。**

## 3. 根本根因：环境层 IK 非确定性

> **与控制模式的关系（避免误读）**：本节诊断的是"IK+CTC 控制路径"内的求解器非确定性。§9 之后环境默认控制模式为 OSC（控制内环不再解 IK），但 OSC 模式下环境 reset 的初始落位仍调用一次 IK，且 §3–§6 的全部实验数字都是在 `UR5E_CTRL_MODE=ik` + `UR5E_IK_BACKEND=pin` 下取得的——两条开关正交，复现时需注意。

### 3.1 现象与定位

- 同一 seed_offset=100000、同一 BC 策略，三次 50 回合评估：32% / 40% / 36%——超出二项噪声可解释范围；
- 决定性实验：同 seed、同策略、连跑两遍 20 回合：**20% vs 45%**；第 0 步动作逐比特相同，下一帧观测差 6.4e-4；
- reset 确定性验证通过（同 seed 12 次复位完全一致；100 次 reset 初始位偏均值≈0、std≈0.55–0.62mm，在 ±1mm 设计范围内）；
- 排除法锁定唯一运行时随机源：控制器每个策略步调用 **11 次** TRAC-IK（1 次目标 + 10 次导纳子循环）。

### 3.2 机制

`trac_ik.TracIK` 默认 `timeout=0.005s, solver_type="Speed"`：在墙钟预算内做随机重启并返回"当时最好的解"。CPU 负载波动 → 实际迭代次数不同 → 返回解的精度/分支不同 → 亚毫米级轨迹分叉。插装任务的成功判据（深度≥8mm + 接触力窗口）对亚毫米位差敏感（接触动力学放大），于是同一条"策略"在不同运行中是不同的轨迹分布。

**这等价于：训练时奖励信号被乘性噪声污染，评估时指标本身在掷骰子。** 在此之前讨论任何算法优劣都没有意义。

### 3.3 修复（优雅且最小侵入）

`training/algorithm/ur5e_ik.py` 增加后端开关：

```python
self.ik_backend = os.environ.get("UR5E_IK_BACKEND", "pin").lower()  # 默认确定性
# ik()/fk() 按 backend 分发；UR5E_IK_BACKEND=trac 可恢复旧行为
```

- Pinocchio 局部 IK（CLIK）：1.8–2.3ms/call，位姿误差 0.133mm@eps=1e-4，30 次重复求解逐比特一致；
- 未收敛警告改为 `verbose` 门控（避免训练日志刷屏）；
- `fk()` 同步按后端分发（原实现硬依赖 TracIK 单例）。

### 3.4 修复验证

- **确定性**：同 seed、同 BC 策略、两遍 20 回合——成功标志、回合长度、逐帧观测哈希**完全一致**（修复前 20% vs 45%）；
- **求解质量**：BC 全程 rollout 13203 次 IK 调用，>1mm 或 >0.01rad 残差仅 3 次（0.02%），最大 1.43mm/1.87°；
- **基线重测**：BC 50 回合固定种子 **14%（7/50）**，失败分解：43 timeout / 0 fail_contact / 0 fail_workspace。注意失败形态从"越界/接触超限"变为"超时"——确定性求解器的轨迹更保守、不再越界，但插入完成率下降；旧的 32%–40% 是同一分布的噪声采样（TRAC-IK 自身在相同协议下就有 20%↔45% 的摆幅）。

### 3.5 附：对"TRAC-IK 误差很小"的实测回应（1.5mm 真实工况）

实验：目标 = 当前位姿 + 1.5mm 小步（控制器每步实际请求量级），同一查询连解两次，空载 vs 3 核满载，各 200 次调用：

| 后端 | 工况 | 失败率（None） | 同查询解不一致率 | 耗时 mean / p99 |
| --- | --- | --- | --- | --- |
| TRAC-IK | 空载 | 1.0% | **11.5%** | 0.63ms / 4.9ms |
| TRAC-IK | 满载 | 0.5–2.0%（随负载升） | **18.0%** | 1.32ms / 4.3ms |
| Pinocchio | 空载 | 0% | **0%** | 4.3ms / 38ms |
| Pinocchio | 满载 | 0% | **0%** | 7.8ms / 41ms |

要点：

1. **TRAC-IK 收敛时的精度确实不差**（实测平均到位误差 ~0.085mm）——问题从来不是收敛精度，而是**同一查询返回哪个解是随机的**（随机重启种子逐次变化）；
2. **失败即冻结**：wrapper 失败返回 None，控制器 `if q_target is None: q_target = q_now`——整步动作被静默丢弃；导纳子循环内失败同理冻结子步。11 次调用/步 × 1–2% 失败率 ≈ 每步 10–20% 概率出现冻结子步，且何时冻结取决于墙钟负载；
3. **1.5mm 是命令位移，不是精度余量**：成功/失败的分界在插入段的横向对准余量上——成功回合 min_xy 均值 0.04mm vs 失败 0.63mm。0.085mm 级到位噪声 + 随机冻结子步正落在这个余量尺度内，再经 400 步接触混沌放大，就是端到端实测的 20% vs 45%；
4. Pinocchio 的代价：局部求解器，远目标会不收敛（0.05rad 关节偏移的远目标实测失败）——但控制器每步只问 1.5mm 近目标，真实 rollout 全程 0.02% 未收敛，且收敛性确定。**换来的收益是逐比特可复现**，这是做一切算法消融的前提。

## 4. 评估协议修正

固定种子批次（seed_offset=100000）下，n=10 的二项噪声 σ≈13–15%，"稳定上升不掉"在统计上不可判。训练脚本新增 `SS_EVAL_EPISODES`（默认 10），本轮验证用 **n=20**（σ≈9%）；最终模型以 n=50 复验。

### v13：超时按无限视野 bootstrap（Pardo et al. 2018 时间极限处理）

采集器把 `done = terminated | truncated` 直接喂给 TD 掩码：**超时步被当作"价值=0 的终点"**。本任务 ~85% 回合以超时收场，且超时状态绝大多数停在孔区附近——critic 被反复教"孔区停留→吸收态零价值"，γ=0.997 下该零值向回合起始回传 ~333 步，把整段失败轨迹（无论离成功多近）的价值压平。这直接解释 v10–v12 的共同病征：**探索策略能找到成功（succ50 20–26%），确定性策略却始终贴着基线**——"向插入区推进"与"继续游荡"的价值对比被伪终点系统性压没。

修复（rl_utils.py）：buffer 拆分为 `dones`（TD 掩码，仅 terminated）与 `ep_ends`（回合切分，terminated|truncated）；超时步的 next_states 本就是 final_observation，可正确 bootstrap。改动不触碰奖励与残差结构，属标准时间极限修正（Pardo et al., "Time Limits in Reinforcement Learning", ICML 2018）。

### v13 结果与 critic 探针

v13（超时 bootstrap 修复）：eval 20 / 10 @12k/24k，仍平贴基线。但对 checkpoint 的定量探针揭示了更深一层：

**探针 1（价值传播）**：沿演示轨迹 Q 分段均值 −4.22→−2.42（Δ=+1.0~1.8）——**critic 已学会演示价值地形，修复生效**。
**探针 2（残差方向）**：Q(ã_policy)−Q(0)=+0.005——actor 在沿正确方向用力，但残差球内可用对比度只有 ~0.5%。
**探针 3（熵标定）**：checkpoint 内 α=0.0115。γ=0.997 有效视野 333 步把每步熵项放大 333 倍：α·(−logπ)·333≈2000α·(−logπ)/6… 实测 soft-Q 中熵项累积量级 ~5–7，**5 倍于成功奖励 R_succ=1**；且 target_H=−d+d·log ε=−23.97 迫使探索 σ≈0.0045（tanh 前空间）——**SAC 的探索实际处于关闭状态**。
**探针 4（动作面可识别性，v14 checkpoint）**：距成功 30 步的演示状态上，沿专家修正方向 ∂Q/∂t=+0.162/unit vs 随机正交方向 +0.044/unit，专家方向更优仅 5/8 回合——**critic 对"往哪边修"的方向导数识别微弱，接近抛硬币**。残差球内可用 ΔQ≈0.008，与 bootstrap 噪声同量级。

## 6. 根本性判断（回答"是不是算法或环境条件有根本问题"）

**环境层**：存在一个根本问题，已修复——TRAC-IK 墙钟超时非确定性（§3）。附带发现：接触动力学对亚毫米位差混沌敏感，任何"单次测量"都不可信，必须固定种子 + 逐帧验证。

**算法层**（冻结 BC + 残差 SAC + 纯稀疏，在本任务上）：发现并已修复四个真实缺陷——超时当终点（v13）、UTD 欠训练 60 倍（v12）、目标熵随 ε 塌缩导致探索关闭且熵项淹没奖励（v14）、γ 视野过长（v15）。**六个配置（v10–v15）在确定性环境下全部平贴基线后，剩余约束可以定量锁定**：

- 残差球内单步动作对结局的 Q 对比度 ≈ **0.008**（探针 2/4 实测）；
- critic 拟合残差 ≈ **0.17**（Huber 0.0015, β=10 换算），且 γ 从 0.997→0.99 不变——是自洽 bootstrap 解的内禀抖动；
- **信号/噪声差 20 倍**；方向探针命中率 5/8 ≈ 抛硬币。

成因链：单步残差的物理影响 ≤0.075mm × 成功依赖 50–200 步持续修正 × 长视野 γ 衰减 × 接触混沌对亚毫米位差的放大 ⇒ 单步信用信号被稀释到 critic 噪声地板以下。**这是"小幅度残差 + 长视野 + 纯稀疏奖励 + 接触任务"的结构性错配，不是实现 bug，也不是预算问题**（critic 已收敛；再跑更久只会更精确地拟合同一个不含方向信号的表面）。任何依赖 ∂Q/∂a 的 actor（SAC/MPO/AWAC 同理）在此尺度都拿不到坡度。

**可行方向（按文献与机制依据排序）**：

1. **任务结构分层**：把"接近→对准→插入"拆成带各自终止条件的子阶段（HER/课程式 episode，非奖励塑形），把 333 步信用链切成 3 段 ~100 步——直接攻击信号稀释的根源。插装类工作的标准做法（Schoettler et al. 2020 工业插装 RL 均为分阶段）。
2. **残差作用对象上移**：残差输出改为"子目标位姿偏移/关键帧参数"（一次决策管 N 步），把序列信用问题还原为单步信用问题（options/参数化动作空间，Residual Policy Learning 原文的实际用法之一）。
3. **critic 方差压制**：REDQ 式 10 头集成 + 大 batch（方差 ↓10 倍，0.17→~0.05），与方向 1/2 叠加才有意义，单独做仍差 6 倍。
4. ε=0.10 在确定性环境重测可作为消融补全（旧"更差"结论出自非确定环境，已作废），但探针 2 显示 ε 球远未饱和，预期不改变结论。

## 9. OSC 改造与验证

### 9.1 实现

按调研结论（SERL franka_sim `opspace.py` 范式）在 `training/algorithm/controllers.py` 为 `UR5eController` 新增 OSC 路径，环境变量 `UR5E_CTRL_MODE=osc|ik` 切换（默认 osc，IK 路径完整保留）：

- **任务空间 PD + 动力学一致投影**：τ = JᵀΛẍ_des + Nᵀτ₀ + qfrc_bias；Λ = (JM⁻¹Jᵀ + λ²I)⁻¹（λ=0.01 奇异回避阻尼），N = I − J̄J 为零空间投影，τ₀ 把关节姿态拉向 home 键位
- **控制频率 1kHz**（每个 1ms 仿真步直接算力矩写 data.ctrl），动作接口不变（笛卡尔位姿增量，pos 1.5mm/step、ori 0.01rad/step），BC 基座与残差栈无需改动
- **导纳环节完整保留**（每 5ms 子迭代读校准力、偏移目标位姿，与原 IK 路径同参数）
- 三个实测逼出来的关键设计：

1. **速度前馈**：斜坡目标速度送入阻尼项（kd·(v_des−v)），消除低刚度下的跟踪滞后（2mm 阶跃 50ms 残差从 37% 降到与 IK 内环相当）
2. **接触门控**：||F||>2N 时撤除前馈——否则被挡住时 kd·v_des 退化成 ~27N 恒推力（实测 25-31N）
3. **笛卡尔反馈力限幅** 6N：||Λ·ẍ_des|| 超限即截断。接触冲击下自动软化，消除 50N+ 力超限终止

### 9.2 调参记录（全部 n=50 固定种子，同 BC 基座）

| 配置 | 成功率 | 失败分解 |
| --- | --- | --- |
| IK+CTC 基线（pin） | **7/50 = 14%** | 全超时 |
| OSC kp2500 无前馈无限幅 | 0/50 | 22 越界 + 28 超时（跟踪滞后致动力学失配） |
| OSC kp10000 | 0/50 | 47 力超限（过刚） |
| OSC kp6000 | 0/50 | 29 力超限 + 18 越界 |
| OSC kp2500+前馈 | 0/50 | 前馈变恒推力 |
| OSC kp2500+前馈+门控 | 0/50（单种子 maxF=42.7N） | 冲击瞬态力超限 |
| OSC +门控+限幅15N | 2/50 | **36 越界但深度已达 9.1-9.5mm**（物理上插入最深，卡在坐底判据的侧向力条件） |
| OSC +门控+限幅10N | 1/50 | 41 越界 |
| OSC +门控+限幅6N | **3/50 = 6%** | 47 超时，0 力超限 0 越界（最干净的失败谱） |
| 分轴阻抗（xy 800/z 2500） | 1/50 | 47 超时 |

最终默认：kp_pos=kp_ori=2500、临界阻尼、限幅 6N。

### 9.3 验证结果

- **确定性：通过**。同 seed 同 BC 策略两遍 20 回合逐帧哈希完全一致（OSC 全程无 IK 求解、无随机重启，确定性是构造性保证）
- **速度：约 2 倍提升**。127s/20回合 vs IK 路径 259s/20回合（省掉每策略步 11 次 IK 求解）
- **BC 基线：6%（3/50）vs IK 14%（7/50）**。未达到 parity

### 9.4 结论与判断

OSC 改造在工程目标上成立：无 IK、确定性、2 倍速、接触安全（0 力超限）、且机械插入能力强于 IK 路径（限幅 15N 时 36/50 回合物理插入到 9mm+，超过成功深度 8mm——失败在坐底判据的侧向力 ≤0.45N 条件，而非进不去）。

BC 成功率低于 IK 基线（6% vs 14%）的根因是**动力学分布失配**：BC 是在 IK+CTC 动力学下采集的演示上训练的，OSC 的接触响应谱（力-位曲线、搜索阶段的摩擦-滑动行为）不同，观察到的力特征分布偏移导致 BC 搜索策略失效。这不是 OSC 的实现缺陷——恰恰是残差 RL 要在线修正的那类失配。要公平评估 OSC 对管线上限的影响，应在 OSC 环境下跑残差训练（环境侧已就绪：`UR5E_CTRL_MODE=osc` 一条环境变量切换），或在 OSC 环境下重采演示重训 BC 基座。

- 权威代码：`sac_gail_ur5e_最终版/controllers.py`；调参日志与脚本备份：`osc_implementation_20260918.tar.gz`

### 9.5 腕部 F/T 传感器惯性补偿（标准处理链第 3 层）

**动机**：§9.2 的最佳配置下导纳与坐底判据使用的校准力仍含工具惯性力——原 `ForceCalibrationSim` 只做第 1/2/4 层（偏置、重力、滤波），运动中无接触时校准力残差 max 0.396N / mean 0.211N，正对 ±0.45N 侧向力判据的裕度。

**实现**（`controllers.py::_tool_inertial_wrench` + `force_calibration.py::update` 新增 `inertial_ft` 参数，环境变量 `UR5E_FT_INERTIA_COMP` 开关，默认开）：

- 标准 Newton-Euler 工具逆动力学：F = m·a_com，T = I_c·α + ω×(I_c·ω) + r_com×F；参数（m、I_c、CoM）直接取 MuJoCo 编译模型，仿真内补偿无损
- 加速度用 `mj_objectAcceleration` 精确获取——**注意坑：MuJoCo 的 cacc 是固有加速度（含 −g，静止时读 +9.81），必须加回 `model.opt.gravity` 才是坐标加速度**（第一版漏了这项，补偿引入 m·g=5.85N 常值误差，实测抓出）
- 参考方案：rahulbachina/robotics-skills（dynamics-force 四层处理链）、Isaac Lab 仿真 RL 的 Inverse-Dynamics Wrench Source、真机 Franka 的 pdz_ft_sensor 补偿节点

**验证**：

| 测试 | 补偿 OFF | 补偿 ON |
|---|---|---|
| 无接触大加速度扫动校准力残差 | max 0.396N / mean 0.211N | **max 0.073N / mean 0.012N**（≈传感器噪声地板 0.01N，降 18 倍） |
| 确定性（两遍 20 回合逐帧哈希） | 一致 | **一致**（补偿链全程确定） |
| BC 50 回合固定种子（OSC） | 3/50 = 6% | **6/50 = 12%**（44 超时，0 力超限 0 越界） |

惯性补偿把 OSC 模式的 BC 基线从 6% 提升到 **12%**，与 IK 路径基线 14% 基本追平（n=50 二项噪声 σ≈5%，差异不显著）——说明此前 OSC 与 IK 的部分差距确实来自力观测里的惯性伪信号，BC 的力特征观测被净化后搜索行为明显恢复。补偿不改变控制律本身，只净化观测/导纳输入，对残差 RL 训练同为即插即用。
